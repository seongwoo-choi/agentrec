# agentrec v0.7.0

A run can be verified after the fact, any two runs can be read side by side,
and the store says what it costs.

## What changed

- **Verified later** — `agentrec verify <run-id>|latest`, and a **Verify now**
  button on a viewer started with `--allow-run`, run the repository's committed
  `.agentrec.yaml` checks again, today, in the repository the run recorded. The
  result is filed under the run as `verification-posthoc/`, carrying its own
  attribution (`verification_observed (post-hoc)`), the time it ran, and whether
  HEAD has moved since the run's baseline. It is shown as its own **Verified
  later** section under the run's own verdict, never in its place, and the page
  says in plain words that it measured the repository as it is now rather than
  the tree the run left behind. A run a recorder still holds, a repository that
  is gone, and a config that is missing, untracked or edited are all refused
  rather than guessed at. `agentrec verify` reports the verdict to the shell the
  way a traced run does: anything but a pass exits non-zero.
- **Compare any two runs** — the run page opens a sheet listing every other
  recorded run; picking one draws the two together: provider, model, started,
  duration, exit reason, usage, actions and events, verification and repository
  status, and the files each one changed, split into only-here, only-there and
  both. The comparison is addressable (`#compare=a,b`) and reads only what the
  page already serves.
- **What the store costs** — `agentrec status` reports the store's size on disk
  and, when it holds anything, the trash's; the viewer's sidebar carries the
  same number. `agentrec trash sweep <age>` (`30d`, `12h`, `2w`) moves runs that
  started longer ago than that into the trash, keeping any a recorder still
  holds, and `--dry-run` lists what it would move without moving it.
- **Following a live run got cheap** — a viewer used to copy a run's whole
  action and event streams on every snapshot, a few seconds apart. It now keeps
  one growing copy per stream and appends only what the run has added since,
  reading each snapshot through the length it captured.

## Known limits

A later verification redacts its check output with a redactor of its own, so a
secret it names is numbered independently of the run's own `[REDACTED:n]`
markers: the same number in the two documents does not mean the same secret.

## Trust

The verify route is the first thing in the viewer that executes anything from a
repository, so it is fenced the way running a comparison is: the per-process
token and same-origin checks every mutation needs, plus `--allow-run`, without
which it is refused; one verification at a time; and the config must be tracked
and identical to HEAD before a single check is pinned — compared with the bytes
HEAD holds, not with git's opinion of whether the file changed, so an index
marked assume-unchanged cannot swap what runs. Those two questions are asked of
the object store with the repository's own hooks and file-system monitor turned
off, so nothing runs before the pinned checks do. The new measurement is built
beside the one already filed and only takes its place once it is complete, so a
re-run that cannot be pinned destroys no evidence. Check output passes
through a redactor before it is written, and a later verification is decoded
only when it carries its own attribution, so it can never be read as the run's
own measurement. The stream cache lives in a directory each viewer makes for
itself, removes the directories of viewers that are gone, and starts a copy
afresh whenever the source is not the same file, has shrunk, or no longer ends
in the bytes the copy holds.

## Upgrading from v0.6.0

Nothing to re-run. A viewer started with `agentrec start` picks up the new
binary on its next start; add `--allow-run` if you want the Verify now button.

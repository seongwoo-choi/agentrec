# agentrec v0.8.0

Failure investigation now starts from the same evidence semantics in the CLI and
viewer, and links preserve the exact run and evidence location under review.

## What changed

- **One failure workflow** — `agentrec list --failures-only` finds explicit
  process failures and terminal verification evidence that did not consistently
  pass. `agentrec show <run-id> --failures-only` reduces that run to failed
  actions and checks while retaining repository context.
- **A failure inbox in the viewer** — **Failures only** uses the same canonical
  failure union as the CLI and composes with search and exact exit or
  verification filters. The sidebar reports shown and loaded counts.
- **Shareable investigation state** — search, filters, the selected run and the
  focused action, change, provider event or verification evidence survive reloads
  in the URL. Missing or unreadable linked runs fail visibly instead of silently
  opening different evidence.
- **Clearer verdicts** — the viewer separates run outcome from verification
  outcome, links failure summaries to their evidence, and refreshes a completed
  post-hoc verification without requiring a page reload.
- **Machine-readable run inventory** — `agentrec list --json` emits a versioned,
  bounded summary with deterministic ordering and an explicit unreadable-run
  count. It composes with the existing list filters without changing human
  output.
- **Executable identity diagnostics** — `agentrec version --verbose` reports the
  executable actually invoked and every executable `agentrec` candidate in PATH
  order, marking candidates that identify the running file.

## Upgrading from v0.7.1

Nothing needs migration. Existing run bundles, post-hoc verification generations
and viewer URLs remain readable. Restart a viewer started by an older binary after
upgrading:

```sh
brew update
brew upgrade seongwoo-choi/tap/agentrec
agentrec stop
agentrec start
agentrec version --verbose
```

`agentrec list --json` is a new CLI output schema (`schemaVersion: 1`); it does
not change the persisted run-bundle schema.

## Trust boundary

Failure classification combines recorded provider actions, supervisor-observed
process outcomes and verification-observed results without claiming that an
observed repository change was caused by a particular action. The viewer remains
loopback-only, and its filters and deep links are read-only views over the same
bounded, sanitized artifacts used by the CLI.

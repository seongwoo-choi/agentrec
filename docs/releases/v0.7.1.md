# agentrec v0.7.1

Viewer history stays bounded as the store grows, and post-hoc verification now
publishes one durable, process-safe measurement at a time.

## What changed

- **Bounded viewer history** — the viewer pages runs through a persistent,
  repairable run index instead of scanning and sorting the entire store for
  every request. Initial deep links still open runs outside the first page, and
  polling reconciles deleted, repaired and unreadable rows without rebuilding
  unchanged DOM.
- **Safer viewer lifecycle** — an existing viewer is stopped through an
  authenticated loopback self-stop request bound to its process and executable
  identity. Identity challenges are not reflected in responses or retained in
  the startup environment.
- **Confined storage cleanup** — trash operations and viewer-cache eviction and
  shutdown cleanup use held directory identities, reject symlink or pathname
  replacements and surface cleanup failures instead of mutating an unexpected
  location or reporting false success. Trashing a run is refused while its
  post-hoc verification lock is held.
- **Consistent integrity status** — tainted verification, repository mutation
  warnings and lost sessions now use the same backend status calculation in
  list and detail views. Repository mutation contributes to the aggregate
  warning count.
- **Bounded snapshots and parsing** — snapshot reads and JSONL/change parsing
  carry cancellation, per-record bounds and shared concurrency limits through
  their full work. Large or unterminated nested change documents fail within
  their declared bounds.
- **Transactional post-hoc verification** — `agentrec verify` and viewer
  verification share a run-scoped cross-process lock. The exact committed
  `.agentrec.yaml` bytes compared with HEAD are the bytes pinned for execution;
  a later pathname replacement cannot substitute another command.
- **Durable verification publication** — completed measurements are retained as
  immutable generations under `verification-posthoc/`. A synced `current`
  pointer is replaced atomically, so an interrupted retry does not delete the
  previous completed result. Legacy v0.7.0 post-hoc directories remain
  readable.
- **Held run identity and cancellation** — staging, cleanup and publication use
  the held run root rather than reopening its pathname. `SIGINT` and `SIGTERM`
  now cancel the verifier context and terminate the verification process group.
- **Executable UI regression gate** — CI runs the JSDOM viewer behavior suite in
  addition to Go formatting, tests, race detection, vet, release-boundary tests
  and builds.

## Upgrading from v0.7.0

Nothing needs migration. Existing flat `verification-posthoc/results.json` and
`meta.json` results are read as before. The next successful post-hoc verification
creates an immutable generation and `verification-posthoc/current`; older
completed generations are retained.

A viewer started with `agentrec start` picks up the new binary on its next
start.

## Security boundary

A committed verification configuration is trusted executable code. agentrec
observes the check leader without reaping it, terminates processes that remain in
the launched process group, and only then reaps the leader. This includes a
background child left by a successful group leader. It is still not a process
supervisor or sandbox and cannot contain a committed check that deliberately
creates another session or process group. Review `.agentrec.yaml` before running
it.

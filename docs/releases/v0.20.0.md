# agentrec v0.20.0

## Continue reading a recorded session

The Viewer links other loaded records whose recorded provider, session ID and canonical repository identity match. This helps revisit earlier recording windows after ending and resuming a coding session.

- Matching identity is a metadata relationship, not proof of a causal resume edge or task success.
- Each run keeps its own requests, repository observations, usage and verification. Nothing is summed or merged.
- Incomplete or ambiguous identity stays unlinked. Project basenames and empty session IDs are not matching keys.
- Only loaded records are considered; the bounded display is not a claim that every historical record was found.
- Links open existing records. They do not execute or resume a provider CLI.

## Development evidence

The work began with ordinary UI test maintenance across planned stops/resumes in one actual Claude Code session. The change adds guards for canonical result.exitCode, positive same-request continuation and repeated command identity. Existing-behavior tests are PINs, not fabricated REDs. Planned pauses and a controlled task are not presented as spontaneous interruption or long-term adoption evidence.

The session-linking feature has its own failing-first tests and preserves existing recording artifacts. Browser, repository and independent review evidence remain separate from provider-reported results.

## Upgrade

```bash
brew update
brew upgrade seongwoo-choi/tap/agentrec
agentrec version --verbose
```

```bash
go install github.com/seongwoo-choi/agentrec/cmd/agentrec@v0.20.0
```

Restart the identified Viewer to use the installed version, preserving its flags and recording store. Refresh an already-open page to load the new UI.

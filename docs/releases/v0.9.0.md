# agentrec v0.9.0

Local automation can now move from a machine-readable run inventory to the
normalized evidence for one selected run without parsing terminal output or
starting the viewer.

## What changed

- **Machine-readable run detail** — `agentrec show <run-id>|latest --json`
  emits a versioned document containing the selected run ID, normalized action
  summaries, and provider-usage, supervisor, repository and verification
  evidence.
- **Failure-only composition** — `--json` composes with `--failures-only` in
  either flag order, completing the `list --failures-only --json` to
  `show <run-id> --failures-only --json` workflow.
- **Stable empty states** — action and evidence collections are explicit empty
  arrays rather than `null`, so local tools do not need a second decoding path.
- **Preserved human output** — the existing terminal report and exit semantics
  are unchanged. Unknown or duplicate flags still return the usage error.

## Upgrading from v0.8.0

Nothing needs migration. Existing run bundles and viewer APIs are unchanged.
Restart a viewer started by an older binary after upgrading:

```sh
brew update
brew upgrade seongwoo-choi/tap/agentrec
agentrec stop
agentrec start
agentrec version --verbose
```

The `--json` output of `agentrec show` introduces CLI output schema `1`; it
does not change the persisted run-bundle schema.

## Trust boundary

The JSON renderer reuses the same held-directory, identity-checked and bounded
run reader as the terminal report. It emits explicit projections instead of
marshalling internal report structs. Provider-controlled metadata, action
summaries and evidence fields are control-escaped and capped, and raw provider
`Input` and `Result` payloads are not included. Repository observations remain
separate from provider-reported actions and do not imply causation.

# agentrec v0.1.0 — release candidate notes

> **Not published.** No `v0.1.0` tag exists in this repository and no GitHub
> release has been created. These notes describe the candidate as it stands on
> `main`; tagging, publishing, and licensing are separate decisions that have not
> been made.

First candidate for a public cut of agentrec: a local flight recorder for
non-interactive Claude Code and Codex runs.

## Evidence model

A run bundle keeps four observers apart, and each carries its own recorded
attribution string rather than leaving the reader to supply one:

| Layer | Attribution | What it does not say |
|---|---|---|
| Provider-reported actions | `provider_reported` | Nothing is verified — this is what the agent said it did. |
| Supervisor-observed result | `supervisor_observed` | Nothing about what happened inside the process. |
| Repository-observed changes | `observed during run, not causal proof` | Not that the agent caused the delta. |
| Verification-observed result | `verification_observed` | Not how the work was done, only how pinned checks ended. |

Statuses are recorded rather than inferred. Repository evidence is `AVAILABLE`,
`UNAVAILABLE`, or `PENDING`; verification is `PASS`, `FAIL`, `TIMEOUT`,
`ERROR`, or `TAINTED`. A `PENDING` run's zero counts mean *not measured*, not
*measured as nothing*, and a run with no verification renders `(none)` rather
than anything resembling a pass.

## Core capabilities

- **`agentrec trace <claude|codex> [--verify] -- <args...>`** — records one
  non-interactive run. Provider version is probed and range-checked
  (`claude >=2.1.0,<3.0.0`; `codex >=0.144.0,<1.0.0`), the invocation is prepared
  explicitly, and the recorded argv is the command that actually ran.
- **Pre-run gating** — the repository is locked per checkout (non-blocking; a
  second concurrent run is refused, not queued) and required to be clean, so the
  run's own changes can be told apart.
- **Pinned verification** — `.agentrec.yaml` and its SHA-256 are fixed before the
  provider starts. Commands are launched directly, with no shell. If the run
  rewrites the config, the verification is recorded `TAINTED` with reason
  `config_changed` and nothing is executed.
- **Structural redaction** — provider events and stderr are sanitized before
  persistence; each match becomes `[REDACTED:n]`, and the rule set version is
  stamped into every manifest.
- **Deterministic reporting** — `report.md` is written into the bundle before
  anything is printed, created once and never overwritten. `agentrec show` is
  read-only. Both renderers escape every dynamic value.
- **Graceful signal handling** — SIGINT and SIGTERM both stop the provider's
  process group, finalize the manifest, measure the repository, write the report,
  and exit `130`.
- **`agentrec list [--cwd <path>]`** — runs newest first with a `PROJECT` column
  derived from the manifest's working directory; `--cwd` matches one absolute,
  cleaned directory exactly, never a prefix.

## Dogfood validation

Full inspection: [docs/dogfood/2026-07-28-evidence.md](../dogfood/2026-07-28-evidence.md).

- A fixed 20-attempt checkpoint across 4 repositories and both providers.
- 5 runs qualify on all three independent sources at once — provider exited
  `completed`, a non-empty repository delta, and pinned checks `PASS`.
- 4 failure modes each produced a complete, readable bundle: verification `FAIL`,
  provider nonzero exit, config `TAINTED`, and an interrupted run.
- 2 pre-fix runs killed before finalization are preserved as `PENDING`/`unknown`
  rather than as runs that changed nothing.
- 3 follow-on mutation runs recorded real changes to this repository, each landing
  in a commit and each verified `PASS`.

## Known limitations

- **Not syscall-complete.** Nothing observes the agent while it works.
- **Repository delta is not causal attribution.** Concurrent edits by anything
  else land in the same delta.
- **A zero redaction marker count is not a secret-absence claim** — it means no
  rule matched.
- **The interrupting signal is not recorded.** The bundle says
  `exitReason: interrupted`; it does not distinguish SIGINT from SIGTERM.
- **macOS and Linux only.** Process supervision is built for `darwin || linux`;
  Windows is unbuilt and unverified.
- **Non-interactive runs only.** Interactive sessions are out of scope.
- **Prompt capture is deliberately narrow.** A prompt agentrec cannot identify
  unambiguously is left unrecorded rather than guessed at.
- No license has been chosen and no packaged binaries are published; installation
  is from source.

## Verification commands

```bash
gofmt -l .
go vet ./...
go build ./...
go test ./... -count=1 -timeout=420s
go test -race ./... -count=1 -timeout=600s
```

The same set runs in CI (`.github/workflows/ci.yml`) on `ubuntu-latest` for every
pull request and every push to `main`.

## Release status

`v0.1.0` is **not tagged and not published**. Publishing it requires, at minimum,
a license decision, a repository-visibility decision, and a green CI run on the
commit to be tagged — none of which are part of this candidate.

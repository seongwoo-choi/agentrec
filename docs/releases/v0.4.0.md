# agentrec v0.4.0

A recorded session now reads as a conversation, recording and reading back are
one command each, and the viewer explains every word it shows.

## What changed

- **Prompts and replies are recorded** — the `UserPromptSubmit` hook files the
  operator's prompt as a `user.prompt` action and the `Stop` hook files the
  assistant's final message for that turn as an `agent.message` action, paired
  by the provider's own turn id (`prompt-<id>` / `reply-<id>`). Both pass
  through redaction like every other action, and the report shows them as
  `PROMPT` and `MESSAGE` lines around the tool calls they bracket. The payload
  fields (`prompt`, `last_assistant_message`, `prompt_id` / `turn_id`) were
  confirmed against the official hooks references and live against Claude Code
  2.1 and Codex 0.150 in `codex exec`. A hook installed in both the user's and
  the project's settings fires twice; each tool call, prompt and reply is still
  filed once (a doubled delivery is the same turn, text and `stop_hook_active`
  within two seconds), and a turn a stop hook continued keeps both replies. A
  report detail is always one line, with control characters dropped, so a
  prompt cannot write to the terminal. `prompt.txt` is bounded to what every
  reader opens (1 MiB); a longer first prompt is cut there with a note, and
  the `user.prompt` action holds what the payload limit allowed.
- **`agentrec setup`** installs the hooks into `~/.claude/settings.json` and
  `~/.codex/hooks.json` (or the project's files with `--project`): existing
  hooks are kept, a backup is written beside the file, and running it again
  changes nothing. On a terminal with no flags it asks which agent to record,
  whether to run the pinned checks (`--verify`), and where to write, then
  prints the equivalent flags. `hooks print` still shows the fragment.
- **`agentrec start`, `stop`, `status`** — `start` keeps the viewer running in
  the background at `http://127.0.0.1:7788/` (pid, URL and log under the data
  directory's `viewer/`) and opens the browser; `stop` ends it; `status` reports
  the viewer, the run count and whether the hooks are installed per provider.
- **An open session reads as `running`** — `list`, `show` and the viewer probe
  the session's recorder lock. Only a bundle nobody holds and nobody finalized
  says `unknown`, and `Ended By` says so in plain words instead of claiming a
  storage failure.
- **Viewer** — redesigned for reading: light and dark palettes, a 14px base,
  panels that scroll on their own, a run list that names the project, age and
  verdict and refreshes in place every 5 s, metric tiles that carry a one-line
  explanation under every status (`UNAVAILABLE` says no checks were run and how
  to turn them on; the session's supervisor status reads `NOT OBSERVED` with
  why; `RUNNING` and `PENDING` say what they wait for), per-line diff colour in
  the patch view, conversation rows for prompts and replies, and an empty state
  for an empty store. The interface is available in English, 한국어, 日本語 and
  简体中文, chosen from the browser language and switchable in the top bar; the
  documented status tokens stay English, the explanations beside them are
  localized, and provider content is never translated.
- **Terminal detection** for `setup` asks the kernel (`termios`) rather than
  checking for a character device, so `agentrec setup </dev/null` in a script
  is not asked questions.

- **One delivery never ends the recording of the ones after it** — a line
  that outgrows the stream only once redaction has replaced its secrets (or
  a dropped delivery's stub carrying a huge `error`) is no longer a failure
  of the whole bundle: the entry is filed as its envelope with a note saying
  what was dropped, and recording continues. The recorder's signal
  subscription now precedes the socket bind, so a signal arriving the moment
  a hook can see the recorder ends the run properly instead of the process.

## Known limitation

A prompt or reply that begins like JSON (`{"…`, `[{…`) but does not parse is
recorded as a single `[REDACTED:n]` marker everywhere, by the redaction rule
that fails closed on JSON it cannot read. The rule is unchanged in this
release; conversation text makes it visible more often than tool payloads
did. A reader who sees a whole prompt replaced by one marker should read it
as "not readable", not as "a secret".

## Upgrading from v0.3.0

Run `agentrec setup` once more: it adds the `Stop` hook to an existing
installation and leaves everything else as it is. Until then `agentrec status`
reports the hooks as installed for 5 of 6 events, and sessions record tool
calls and prompts but not replies. Sessions already open when the hooks change
are recorded by the recorder they started with.

## Verification

`gofmt -l` clean, `go vet ./...`, `go test ./...` on every package; the README
localization gate; a live `claude -p` session recorded through the printed
fragment (`PROMPT` → `SHELL` → `MESSAGE`, one action per delivery); live hook
payload captures from Claude Code and `codex exec`; the interactive `setup`
driven on a real pseudo-terminal; `start` / `status` / `stop` against a real
store.

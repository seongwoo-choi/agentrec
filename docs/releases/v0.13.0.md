# agentrec v0.13.0

Keep the run list focused without deleting recorded evidence. The Viewer now
shows the newest ten matching loaded runs by default and lets you narrow them
by an exact project name.

## What changed

- Choose an exact project name alongside search, exit, verification and failure
  filters. Project choices and matches cover browser-loaded runs, not a new
  store-wide query; Load more still extends that set.
- Reveal or fold earlier matches. A selected older matching run stays accessible
  once, while the open evidence remains unchanged when you filter the sidebar.
- Remember the last project choice on a bare landing page. The applied choice is
  written into the URL; explicit project values, including All, take precedence.
  Legacy shared filter links and direct run/evidence/compare links do not inherit
  an unrelated saved project.
- Show separate displayed, matching, loaded and folded counts. Empty search and
  unreadable-page messages describe loaded evidence rather than claiming the
  entire store is empty.
- Preserve expansion through polling and loading more. If an incoming run folds
  the keyboard-focused cutoff row, focus moves to the earlier-runs control.
- Refresh exhausted-page controls even when only paging metadata changes.
- Provide the controls and scope explanations in all four Viewer languages.

## Upgrade

```bash
brew update
brew upgrade seongwoo-choi/tap/agentrec
agentrec version --verbose
```

Direct Go installation:

```bash
go install github.com/seongwoo-choi/agentrec/cmd/agentrec@v0.13.0
```

## Trust boundary

Filtering and folding only change presentation. They do not delete, archive,
expire or modify recorded evidence, and project names are not used to infer
that a run is a disposable test. Exact action and changed-file links retain
their existing evidence boundaries. Project selection is local browser state,
not a storage schema change or access-control rule.

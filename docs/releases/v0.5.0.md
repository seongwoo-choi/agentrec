# agentrec v0.5.0

The viewer becomes a place to work in, not only to read: runs can be deleted
(into a trash), the timeline scrolls, a session's usage is read from the
provider's transcript, and — when you say so — a comparison of two runners
can be launched from the page.

## What changed

- **Delete a run from the viewer, with undo** — a run deleted in the viewer
  is moved to `<data>/trash/<run-id>`, never erased; an Undo restores it. The
  request needs a token only the viewer's own page can read, sent in a header
  no cross-site request can carry, from a same-origin fetch. A run still being
  written is refused: a session whose recorder holds its lock, a trace whose
  repository lock is held, an unfinished run touched within the last hour, or
  one whose close-out has not filed the report yet. `agentrec trash` lists the
  trash, `trash restore <run-id>` brings a run back, `trash empty` erases.
- **Infinite scroll** — actions, changes and provider events load as the
  timeline scrolls; loaded rows, selection and focus survive appended pages.
  Provider events delivered by hooks are labelled by their hook event name with
  a useful detail instead of "(untyped)".
- **Usage, model and version from the transcript** — the hooks carry no token
  usage, but the transcript they name does. At session end the recorder reads
  it once — Claude Code's JSONL (per-response usage deduplicated by request id,
  the model, the version that wrote the last line; placeholders skipped) or
  Codex's rollout (each `token_count`'s last usage, the turn's model, the CLI
  version) — counting only lines written since the run started, and files it
  as provider-reported usage with `Source: transcript` and the model named.
  Fields the provider never wrote stay unreported; the provider's version lands
  in the manifest. A FIFO or an oversized file at the transcript path cannot
  hold the recorder.
- **Three words for three absences** — `NOT RUN` (no verification was
  requested), `NOT OBSERVED` (no process was supervised: a session agentrec did
  not launch), `NOT RECORDED` (no repository measurement) replace the one word
  `UNAVAILABLE` in the list, the report and the viewer. In the viewer's other
  languages the status words themselves are localized, with the English token
  in the tooltip.
- **Compare runners from the viewer** — `agentrec view --allow-run` (or
  `agentrec start --allow-run`) lets the page launch `agentrec shadow run` in a
  repository you name, with a task you type and the runners you tick, and shows
  the command's output as it comes and the two runs it recorded. Without the
  flag the panel only writes the command for you to copy. One comparison runs
  at a time; Cancel interrupts it the way Ctrl-C would. The repository needs a
  committed `.agentrec.yaml`, as `shadow run` always did.
- **A traced run is recorded once** — a provider that agentrec launches
  (`trace`, a shadow leg) carries `AGENTREC_HOOKS=1` in its environment, and
  the hook command installed by `agentrec setup` says nothing when it sees it,
  so the run is not filed a second time by a session recorder.
- **Viewer** — a language switcher (English, 한국어, 日本語, 简体中文), every
  status word explained beside it, conversation rows for prompts and replies.
- **README** — real screenshots of the viewer, clickable to full size.

## Trust

The viewer listens on loopback without authentication, so any process on the
machine that can reach loopback can read every run and, now, move one to the
trash. With `--allow-run` such a process can also launch `agentrec shadow run`
in a repository of its choosing, as you. Leave the flag off unless you want
that. A page from another origin in your browser can do neither.

## Upgrading from v0.4.0

Nothing to re-run: the hooks are unchanged. The viewer's Delete and Compare
controls need the new binary; `agentrec start` picks it up on the next start.

## Verification

`gofmt -l` clean, `go vet ./...`, `go test ./...` on every package (including a
comparison launched through the viewer's API with stub runners); the README
localization gate; adversarial review workflows over the delete, transcript
and comparison code with their findings folded in; the viewer exercised in a
browser against a copy of a real store (delete → undo, paging, four
languages).

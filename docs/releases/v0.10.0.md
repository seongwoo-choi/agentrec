# agentrec v0.10.0

Local automation can now retrieve the exact repository paths observed as changed
in a saved run without parsing terminal output or starting the viewer.

## What changed

- **Structured change inventory** — `agentrec changes <run-id>|latest --json`
  emits schema `1` with the run ID, repository evidence status, attribution,
  baseline and normalized changed-file metadata.
- **Human-readable inventory** — omit `--json` for a visible, quoted terminal
  table. Line counts that do not apply remain `-` rather than becoming false
  zeroes.
- **Viewer parity without Viewer state** — the command reuses the Viewer's
  canonical repository-evidence parsing and validation but does not start the
  Viewer or create its cache.
- **Complete-or-fail output** — inventories larger than 250 files fail closed
  instead of returning a first page that looks complete. Use the Viewer for
  those runs.

## Upgrading from v0.9.0

Nothing needs migration. Existing run bundles, the Viewer APIs, and the
`agentrec show --json` schema are unchanged. Restart a Viewer started by an
older binary after upgrading:

```sh
brew update
brew upgrade seongwoo-choi/tap/agentrec
agentrec stop
agentrec start
agentrec version --verbose
```

## Trust boundary

`changes` reads only the repository evidence stored with the selected run. It
does not inspect the current checkout, and it exposes no patch, file content,
untracked-file hash, storage path, or provider payload. The reader holds the
run directory, rejects symlinked or changing evidence, applies the same bounded
cross-artifact validation as the Viewer, and emits nothing until the snapshot is
consistent. Repository observations remain `observed during run, not causal
proof`.

# agentrec v0.6.0

The viewer follows a session while it runs, and finds a word across every
run.

## What changed

- **Live view of a running run** — while a session (or a trace) is still
  going, the run page keeps up on its own: new actions, prompts and replies,
  and provider events appear as they are filed, the counts and tiles follow,
  and a LIVE pill says when the page last caught up. Every stream page now
  carries `endCursor`, the offset after its last item, so the page reads only
  what is new. The Changes tab of a running run shows the working tree as it
  is now — files with their git status — labelled as a look during the run,
  not the measurement filed when it ends and not proof the agent caused it.
- **Search across runs** — a search field in the top bar looks for a word,
  case-insensitively, in every run: where it happened, its first prompt, and
  its actions — matched only against the same allowlisted input fields the
  reports show (prompt, text, command, file path, query, URL, tool name).
  Hits are grouped by run, newest first; opening an action hit lands on that
  action. The scan stops after four seconds or two hundred hits and says so.
- **Stream pages resume** — `endCursor` is also what lets a search hit open
  the actions stream at the matching line.

## Trust

Nothing new leaves the machine. The live look asks git only what it knows
without reading a file's content — `ls-files` by stat data and `diff-index
--cached` against HEAD — so no clean filter, submodule or hook the repository
configures runs on the page's behalf; the work tree is pinned to the run's
directory whatever the repository's own configuration points at; each call
has a five-second timeout, a killed process group on expiry and a bounded
output. The search reads the store through the same confined root every
other reader uses (a planted link is not followed) and never surfaces an
input field the report would not show.

## Upgrading from v0.5.0

Nothing to re-run. A viewer started with `agentrec start` picks up the new
binary on its next start.

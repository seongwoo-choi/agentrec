# agentrec v0.15.0

The Viewer reads like a record of what happened rather than a dump of what was
logged. Every change in this release was chosen from a measured friction on a
real local store of 35 runs, and each one names its measurement.

## What changed

### Run list

- Rows lead with a safe title derived from the first line of the prompt; the
  run ID stays as secondary metadata. Exit, verification and failure-only
  filters start collapsed under **Advanced filters**.
- Each row shows the recorded duration (`6s`, `14m`, `1h 12m`), agreeing with
  the detail page to the millisecond. Live and duration-less runs show nothing.
- A collapsed **Loaded runs at a glance** disclosure counts loaded runs by
  provider, verification result and project, verbatim, never as a rate.
  Clicking a group applies the existing run-list filter.
- Two skip links put the run list and the run evidence one Tab away.

### Run detail

- The heading stops at the title's first sentence; the full title stays in the
  tooltip, the sidebar row and the request card. A colon is not a boundary.
- Beside the request card, a **Last message from <provider>** card shows the
  agent's final message verbatim with its position among the recorded actions
  and a link that reaches the action even beyond the loaded pages.
- The summary strip keeps four cards — process outcome, verification verdict,
  repository evidence, warnings — in four full columns; action and event counts
  live in the tab labels.
- On desktop the timeline and inspector panels take the height left below the
  run context instead of a fixed guess, so a normal run at 1920×1080 no longer
  needs a page scrollbar.
- When the Viewer was started without `--allow-run`, the Verification block
  says how to verify later instead of silently omitting the button.
- The evidence-link caption is the copy button's tooltip and accessible
  description rather than a paragraph above every payload.

### Timeline

- **Reading view** folds consecutive routine tool actions into native
  disclosures; prompts, agent messages, file mutations, failures, warnings and
  unknown states stay individually visible. **All actions** is one toggle away.
- **Changes** groups loaded files by their exact directory; **Provider events**
  folds consecutive `PostToolUse` records and, new here, the `system`
  hook-lifecycle records that are 87% of Claude's event stream. On the largest
  run the event summary drops from 224 to 45 top-level rows with every record
  still in the page.
- Codex `apply_patch` rows name the files their headers touch instead of
  showing `*** Begin Patch`.
- Prompt rows say which turn they are — `You · 3 of 12` — and a prompt that is
  a Claude background-task notification is labelled **Task notification**, not
  **You**.

Everything is a fold, a label or a position: no record, index, byte cursor,
search result or inspector view changes, and nothing infers success, causality
or which reply answers which prompt.

## Upgrade

```bash
brew update
brew upgrade seongwoo-choi/tap/agentrec
agentrec version --verbose
```

Direct Go installation:

```bash
go install github.com/seongwoo-choi/agentrec/cmd/agentrec@v0.15.0
```

## Trust boundary

Every summary, fold, title and ordinal in this release is derived
deterministically from the already-recorded, already-redacted local evidence
and can be expanded to the original record in one click. Nothing is sent
anywhere, nothing is re-read from the provider, and a verification result is
still evidence recorded for that run, not independent proof the task succeeded.

## 1. Evidence model boundaries

**Observed.** Four assurance levels, no ordering implied
(`internal/action/action.go:16`):

| Assurance | Means |
|---|---|
| `provider_reported` | The provider said it did this. Not verified by the recorder. |
| `supervisor_observed` | The recorder watched the process: exit code, reason, duration. |
| `repository_observed` | The recorder diffed the checkout before/after. |
| `verification_observed` | The recorder ran pinned checks after the provider stopped. |

Attribution strings are carried in every report, not supplied by the reader:

- repository: `observed during run, not causal proof` (`internal/evidence/git.go:99`)
- verification: `verification_observed` (`internal/evidence/verification.go:33`)

Statuses are recorded, never inferred:

- git: `available` / `unavailable` / `pending` (`internal/evidence/git.go:51`)
- verification: `passed` / `failed` / `timeout` / `error` / `tainted`
  (`internal/evidence/verification.go:38`) — `tainted` means the pinned config
  changed under the run, so **nothing was executed**.

**Conclusion.** The model's boundary is attribution, not truth. A `PASS`
verification says the checks the operator pinned passed on the tree the run
left behind; it does not say the agent's edits caused the pass. A repository
delta says files differed across the run window; concurrent edits by anything
else land in the same delta. `PENDING` exists precisely so a run killed partway
cannot be misread as a run that changed nothing.

## 8. Security claim discipline

**Observed.** Redaction is rule-based (`internal/redaction/`): field names whose
canonicalized form ends in one of `TOKEN, SECRET, PASSWORD, APIKEY, ACCESSKEY,
PRIVATEKEY, SECRETKEY, SIGNINGKEY, PASSWD, AUTHORIZATION, CREDENTIAL,
CREDENTIALS, COOKIE` (`redactor.go:22`), plus `NAME=VALUE` assignment patterns
(`patterns.go:33`). Each match becomes `[REDACTED:n]`; the rule set is stamped
into every manifest as `redactionRuleVersion: "1"`.

Marker counts in stored streams vary widely: `020e3af4` 131, `83b2b589` 45,
`ab1adf02` 0, `cd8f5483` 0.

**Conclusion.** A zero marker count means **no rule matched this stream**. It is
not evidence that the stream contains no secret. A secret in a field the
suffix list does not name, in prose rather than an assignment, shorter than the
minimum run length, or arriving base64-wrapped past the decode depth bound,
produces the same zero. `ab1adf02`'s 0 and `cd8f5483`'s 0 should be read as
"the rules found nothing", and any statement stronger than that needs a
different instrument.

The same applies to the recorder's guarantees generally: bundles are `0600` and
untracked bodies are hashed over sanitized text, never raw
(`hashBasisSanitized`, `git.go:73`) — precisely because a hash of the raw text
would hand back a short secret by guessing.

- No secret-absence claim from a zero redaction count (§8).
- The signal that interrupted `86390b3a` is not recorded in the bundle (§4).
- `65 -> 76 / 25 -> 0` is not reproducible from committed history; `60 -> 76 /
